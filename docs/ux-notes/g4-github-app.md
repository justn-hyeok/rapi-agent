# G4 GitHub App UX 메모

- 낯선 사람이 `@rapi`를 불러도 **아무 답이 없다**. 소유자가 공개 레포에서 "왜 반응이 없지?"라고 느낄 수 있지만, 답글을 달면 낯선 사람이 App의 댓글을 유발할 수 있어 일부러 침묵한다. 소유자 로그인이 `GITHUB_APP_OWNER_LOGINS`에 빠진 경우도 똑같이 침묵이라 원인을 알기 어렵다(웹훅 Recent Deliveries는 200으로 보인다).
- 변경 요청 판정은 Discord와 같은 한국어 문장 규칙(`routeIntent`)이다. `@rapi 로그인 버그 고쳐줘`는 PR이 되지만 `@rapi fix the login bug`는 질문(읽기 전용 답변)으로 처리된다. 영어 지시가 PR로 이어지지 않는다.
- PR 스레드에서 부른 요청도 **기본 브랜치에서 새 클론**을 만들어 새 PR을 연다. 열려 있는 PR의 브랜치에 커밋을 얹지 않는다. "이 PR 고쳐줘"는 의도와 다른 결과(별도 PR)가 된다.
- 응답은 엔진 메시지를 그대로 댓글로 옮겨서 "작업 …을 접수했습니다 / 실행기 보고 / 상태" 3~4개 댓글이 쌓인다. 스레드가 길어지고 알림 메일도 여러 통 간다. 접수 즉시 붙는 👀는 첫 신호일 뿐 진행률이 아니다.
- 같은 스레드·같은 사람의 요청은 순서대로 처리되고 대기열이 20개를 넘으면 거절된다. 다른 사람(소유자 로그인이 여럿일 때)의 `@rapi 멈춰`는 요청자 단위라 남의 작업을 멈추지 못한다.
- 하네스는 VM 서비스 계정 권한으로 실행된다. 토큰은 환경에서 제거되지만 같은 계정의 `gh` 로그인은 하네스가 쓸 수 있다. 소유자 전용이라는 전제가 이 안전장치의 전부다. 외부 사용자에게 열기 전에 샌드박스가 필요하다.
- 주간 리포트는 `ModelClient`가 아직 연결되지 않아(레인 C6) 요약 문장 없이 목록만 간다. 첫 활성화 직후 월요일 09:00 뒤 3일 안이면 즉시 한 번 발송된다.
- 웹훅 본문은 요청 한 건의 최소 필드만 저장하지만 댓글 내용(`@rapi` 뒤 문장)은 `chat_messages`에 남는다. 보존 정책 대상인지 확인이 필요하다.
- 레포를 App에서 제거하거나 키를 교체하면 진행 중이던 작업의 댓글 게시가 조용히 실패하고 Discord에는 알림이 가지 않는다.
