# UX 메모 모음

각 레인이 남긴 메모(`docs/ux-notes/<lane>.md`)를 우선순위로 묶었다. 세부 근거는 해당 파일에 있다.

## 켜기 전에 꼭 알아야 할 것

- **`WEB_ENABLED`를 켜면 9개 slash 명령이 웹 링크 안내만 한다.** Discord 로그인 redirect를 등록하고
  로그인이 되는지 확인한 뒤에 켠다. 웹은 `identify` scope만 받아 서버 멤버십·관리자 권한을 모른다.
  그래서 서버 단위 설정과 `/사용량`은 사용자 ID 목록에 오른 계정만 쓸 수 있다(w2).
- **비용 상한은 API 경로만 센다.** Codex CLI(ChatOps, 기본 public-agent)의 비용은 집계되지 않는다.
  가격표에 없는 모델은 비용 0으로 기록되어 상한이 사실상 꺼진다(c6).
- **public-agent `api` 전환은 두 곳 설정이 같아야 한다.** 봇 `.env`와 `/etc/rapi-public-agent.env`
  모두 `PUBLIC_AGENT_BACKEND=api`. 하나만 다르면 사용자는 일반 오류만 본다(q5).
- **메일은 업체 웹훅 등록을 코드로 확인할 수 없다.** 첫 발송 후 업체 대시보드에서 웹훅 전달을
  직접 확인한다. 안 되면 반송 주소로 계속 보내 도메인 평판이 떨어진다(m3).
- **블로그는 PR 병합이 곧 게시다.** `[발송]`/`[게시]` 뒤에도 PR을 병합해야 공개된다.
  즉시 내리려면 `RAPI_BLOG_WITHDRAWALS_FILE` 쓰기 권한이 필요하다(m2).
- **GitHub App은 소유자 전용이라는 전제가 안전장치의 전부다.** 하네스는 VM 계정의 `gh` 로그인을
  쓸 수 있다. 외부 레포에 열기 전에 샌드박스가 필요하다(g4).
- 배포 직후 slash 명령을 다시 등록해야 `/작업`·`/승인`이 사라진다(a1).

## 사용자가 헷갈릴 것

- 버튼을 눌러도 원래 메시지가 그대로 남아 처리됐는지 알기 어렵다: 서버 허용(b), 학습자 발송(c).
- 응답 없이 무시되는 경우: 허용되지 않은 서버 안내가 누구에게 요청할지 말하지 않음(b),
  비소유자의 `센파이로`(a2), 비소유자 `@rapi`(g4), 영어 `@rapi` 지시는 PR이 아니라 질문으로 처리(g4).
- 챗봇: 확인을 텍스트("응")로 하면 검색으로 흘러간다. 공개 채널의 확인 버튼이 모두에게 보인다(q5).
- 학습자 DM에 웹 해지 링크(`/u/<token>`)가 아직 없다. 메일 등록 버튼은 처음 놓치면 다시 보기 어렵다(w1, m3).
- 웹 `/admin`의 "구독"(운영자 브리핑)과 `/me`의 "내 구독"(학습자 트랙)이 이름이 겹친다(w2).
- `/검색`의 웹 링크는 결과가 아니라 아카이브 목록으로 간다(w2).

## 운영자가 놓치기 쉬운 것

- 학습자 호 미리보기를 놓치면 그날 호는 나가지 않고 항목도 다음 호로 넘어가지 않는다(c).
- 큐레이션 채널 자동 게시 글은 임베드가 저장되지 않아 학습자 호에 들어가지 않는다(c).
- 하네스 `[반영]` 뒤에도 PR 병합, 배포, `install-senpi.sh` 실행이 남는다(a3).
- 블로그 `approved`에 머무는 글, 닫힌 하네스 PR은 알림이 없다(m2, a3).
- 알림은 월 1회라 한도를 올린 뒤 같은 달에 다시 넘으면 DM이 오지 않는다(c6).
- `/취소`는 옛 작업 기록만 멈춘다. ChatOps 작업은 "라피야! 멈춰"로 멈춘다(a1).

## 측정의 한계

- 공유는 측정할 수 없어 실험 리포트의 "답장·공유"는 답장만 센다(c).
- 웹 아카이브에서 읽은 것은 클릭으로 집계되지 않는다(w1).
