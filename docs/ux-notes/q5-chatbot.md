# UX 메모: 아카이브 챗봇 (L1–L2)과 public-agent 전환

- (U8에서 고침) 구독 변경은 버튼으로만 확정된다. 확인 문구가 "아래 버튼을 눌러 확정해 주세요."로 끝나고, 그 직후 "응/네/ㅇㅇ/yes" 같은 짧은 답은 검색 대신 "버튼을 눌러 확정해 주세요."로 답한다(채널·사용자 단위 직전 24시간 대화 기준).
- "알림 안 받고 싶은데" 같은 문장도 "안 받" 때문에 구독 해지 확인으로 이어진다. 확인 버튼을 눌러야 바뀌므로 피해는 없지만 의도와 다른 질문이 나올 수 있다.
- 공개 채널에서는 확인 버튼이 모두에게 보인다. 다른 사람이 눌러도 "본인의 구독만 바꿀 수 있어요"가 나올 뿐 바뀌지 않지만, 임시(ephemeral) 메시지가 아니라서 채널이 어수선해진다.
- 맥락은 채널과 사용자 단위다. 스레드가 아닌 채널에서는 같은 사람의 질문이 24시간 동안 이어진다. 후속 질문에도 "라피!" 접두어가 필요하다.
- 한 글자 한글 토큰(그, 글, 더)도 검색어로 센다. 후속 질문 "그 글 더 설명해줘"는 점수가 0.375로 기준(0.34)에 겨우 걸친다. 관련성 기준은 실제 질문 로그를 본 뒤 조정해야 한다.
- 이번 주 트랙 미리보기는 사용자의 빈도와 상관없이 최근 7일 후보를 보여 준다. 실제 호는 운영자가 승인해야 나가므로 문구에 "바뀔 수 있어요"를 넣었다.
- 아카이브 색인은 첫 질문(재시작 후, 또는 5분 경과 후)에서 동기화하므로 그 질문이 조금 느릴 수 있다. 블로그 글은 `RAPI_PUBLIC_BASE_URL`이 있어야 색인된다.
- 챗봇을 켜려면 봇 `.env`와 `/etc/rapi-public-agent.env` 둘 다 `PUBLIC_AGENT_BACKEND=api`여야 한다. 하나만 다르면 사용자는 "공개 질문 실행기를 사용할 수 없습니다. 운영 상태를 확인해주세요."만 본다. 봇 쪽은 시작할 때 실패하지만 실행기 쪽 설정은 요청 때에야 드러난다.
- `api` 백엔드에서 게이트웨이가 5xx를 주면 실행이 시작된 것으로 기록되어 사용자의 일일 한도가 차감된다(codex 실행 실패는 차감하지 않는다). 월 한도 도달 응답도 한 번의 사용으로 센다.
- `public-agent:install`은 `api` 백엔드로 바꿔도 codex 바이너리를 찾고, `auth.json`이 없으면 `codex login`을 시도한다. 전환 후에도 이 단계가 남는다.
- `PUBLIC_AGENT_BACKEND=api`만 켜고 챗봇을 끄면 기존 공개 질문 프롬프트가 "웹 검색을 우선 사용한다"고 말하지만 모델에는 검색이 없다. system 프롬프트가 검색과 만들어 낸 링크를 금지하므로 모른다고 답한다. 문서의 중간 상태("아카이브 글 링크 안내")는 만들지 않았다. 챗봇을 켜야 그 역할을 한다.
- `/데이터삭제` 미리보기 건수에는 챗봇 대화가 들어가지 않는다. 확정하면 함께 지워진다.
- 개인정보 워커는 15초마다 `chatbot_turns`를 지운다. 0025 마이그레이션을 먼저 적용하지 않고 워커를 재시작하면 매 주기 실패 로그가 남는다.
- L2 에러 설명에 붙여 넣은 텍스트는 비밀값 마스킹(`redactChat`)을 거치지만 완벽하지 않다. 사용자가 토큰이 든 로그를 붙이면 모델 공급자에게 간다. 안내 문구로 경고하는 방안은 열 때 정한다.
- 공개 GitHub API는 인증 없이 IP당 시간당 60건이다. 인기 있는 레포 설명 요청이 몰리면 "그 레포를 읽지 못했어요"가 나온다.
