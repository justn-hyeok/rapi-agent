# M2 블로그 게시·초안 UX 메모

- **게시가 두 번 승인된다.** 학습자 소식은 `[발송]`, 가이드는 `[게시]`로 승인하지만 공개는 블로그 저장소 PR을 병합해야 일어난다(정적 블로그가 git 파일을 배포 시점에 빌드하기 때문). 소유자가 PR 병합을 잊으면 글은 `approved`에 머문다. (U8) 승인 후 24시간이 지나도 PR이 열려 있으면 PR 링크와 함께 DM 한 통으로 알린다(글당 한 번, 다시 초안이 됐다가 승인되면 새로 센다).
- **PR을 병합하지 않고 닫으면** 글이 조용히 `draft`로 돌아가고 `[게시]`/`[버리기]` DM이 온다. PR 제목·본문은 영어/한국어 혼합이다.
- **`[내리기]`가 즉시 숨기려면** `RAPI_BLOG_WITHDRAWALS_FILE`이 봇 프로세스에서 쓰기 가능해야 한다. 이 파일은 기본적으로 `source-expiry` 서비스 계정이 쓰는 경로(`/var/lib/rapi/`)라 권한이 없으면 내림 응답이 "PR이 병합될 때까지 남을 수 있어요"로 바뀐다. 설정 전에는 즉시 내림이 보장되지 않는다.
- **승인 대기(`approved`) 글은 내릴 수 없다.** PR이 열린 상태에서 마음이 바뀌면 GitHub에서 PR을 직접 닫아야 한다(그러면 초안으로 돌아간다).
- **`[버리기]`는 되돌릴 수 없다.** 초안 행을 삭제한다. (U8) 첫 `[버리기]`는 같은 메시지에 "정말 버릴까요?"와 `[정말 버리기]`/`[돌아가기]`를 보여 주고, 둘째 버튼이 삭제한다. `[돌아가기]`는 `[게시]`/`[수정 요청]`/`[버리기]`를 복구하므로 PR이 닫혀 돌아온 초안(원래 `[수정 요청]`이 없던 메시지)에도 수정 버튼이 생긴다.
- **초안 미리보기는 5,500자에서 잘린다.** 그보다 긴 글은 PR에서 전체를 봐야 한다. 모델 출력은 모두 평문으로 이스케이프되므로 마크다운 서식(굵게, 목록)은 쓸 수 없다.
- **초안은 `MODEL_API_BASE_URL`/`MODEL_API_KEY`가 있어야 한다.** 봇·chat·워커가 공유 모델 클라이언트(C6)를 받으므로, 없으면 `BLOG_DRAFTS_ENABLED=true`여도 "블로그 초안 기능이 꺼져 있어요"라고 답하고 주간 제안도 돌지 않는다.
- **`블로그 초안:`은 홈 서버의 SUPERADMIN만** 쓸 수 있고, 다른 사람이 보내면 일반 질문으로 처리된다. 같은 메시지가 다시 전달돼도 초안은 하나만 만들어진다.
- **주간 제안은 일주일에 한 번**, 최근 `setup`/`stars` 글 중 아직 쓰지 않은 것 하나를 고른다. 주제를 바꾸려면 `블로그 초안:`으로 직접 요청해야 한다.
- 자동 생성된 슬러그(`guide-<메시지 ID>`)는 읽기 어려운 주소가 된다. 지금은 바꿀 수 없다.
- **주간 제안에서 `[버리기]`를 누르면** 행이 지워져 같은 주제가 다음 시도(1시간 뒤)에 다시 제안될 수 있다. 주제 제외 목록이 아직 없다.
- **`[발송]` 직후 블로그 PR은 최대 5분 뒤에** 열린다(워커 주기). 발송 응답을 기다리게 하지 않으려는 선택이다.
