# C6 모델 클라이언트·비용 상한 UX 메모

- 상한(100%)에 도달하면 공개 기능이 멈춘다. `PUBLIC_AGENT_BACKEND=api`의 공개 질문은 호출하는 쪽이
  한도를 확인하고 실행기가 보고한 사용량을 기록한다(I7). Codex CLI 경로(`codex` 백엔드, ChatOps)의
  비용은 여전히 집계되지 않는다는 점을 소유자가 알아야 한다.
- 공개 기능이 이 클라이언트로 옮겨 가면 `ModelBudgetExceededError`를 받은 호출자가 사용자에게
  보여 줄 문구가 필요하다. 지금은 에러 메시지(영어)만 있고 한국어 안내는 호출자 몫이다.
- 비용 줄은 `/사용량`에서 운영진에게만 보인다. 일반 사용자는 기존 횟수 표시만 본다.
  `MODEL_API_*`가 꺼져 있으면 `/사용량`·`/상태` 출력은 이전과 같다.
- 가격표(`ops/model-prices.json`)에 없는 모델은 비용 0으로 기록된다. LiteLLM 비용 헤더가
  없는 직접 연결에서는 상한이 사실상 작동하지 않으므로, 새 모델을 쓰기 전에 가격표를 채워야
  한다. 이 경고는 로그와 `model_usage.note`에만 남고 Discord에는 알리지 않는다.
- 한도 확인은 호출 전·후 DB 합계를 읽는 방식이라 동시 호출이 많으면 상한을 조금 넘길 수 있다.
  또한 한도 조회가 실패하면 호출을 막지 않고 통과시킨다(기능 중단보다 과금 초과를 택한 것).
- `MODEL_API_BASE_URL`은 loopback이 아니면 HTTPS만 허용한다. LiteLLM을 다른 호스트에 둘 때
  http로 설정하면 시작 시 설정 오류가 난다.
- 요청은 `max_tokens`를 보낸다. OpenAI 직접 연결에서 추론 모델은 `max_completion_tokens`만
  받으므로 그런 모델은 LiteLLM을 거치게 해야 한다.
- (U8에서 고침) 알림은 월·단계·한도 금액별로 한 번씩 간다. `MODEL_MONTHLY_BUDGET_USD`를 올린 뒤 같은 달에 새 한도를 넘으면 다시 온다. 배포 직후 이미 80%/100%를 넘긴 달이라면 새 키 형식 때문에 알림이 한 번 더 올 수 있다.
