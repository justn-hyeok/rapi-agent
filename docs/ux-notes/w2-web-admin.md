# W2 web admin: UX notes

Things a user or the owner may find confusing, missing, or risky.

## 운영자

- **서버 단위 설정은 사용자 ID 목록에 오른 계정만 쓸 수 있다.** 웹 로그인은 `identify`만 받아 서버 목록·역할·Discord 관리자 권한을 볼 수 없다. 그래서 "서버 관리자(Administrator 권한) 또는 관리자 역할만으로 ADMIN"이던 길드 범위 관리자는 웹에서 `/사용정책`, `/서버구성`을 쓸 수 없다. `DISCORD_ADMIN_USER_IDS` / `DISCORD_SUPERADMIN_USER_IDS`에 있는 계정만 된다. 다른 서버 관리자에게 열려면 `guilds` OAuth scope를 추가하고 Administrator 비트를 확인해야 한다(별도 결정).
- **서버 선택은 ID 목록.** 선택지는 운영자 서버와 허용된 서버의 ID만 보여 준다(서버 이름은 모른다). 허용 목록이 비어 있으면 ID를 직접 입력한다. 허용되지 않은 서버는 슬래시 명령과 같은 이유로 거절된다.
- **`/사용정책` 변경은 SUPERADMIN만.** ADMIN은 조회만 된다(슬래시 명령도 같다: 길드 범위가 아닌 ADMIN은 설정에 SUPERADMIN이 필요). 폼은 ADMIN에게도 보이지만 제출하면 403 안내가 나온다.
- **웹훅 비밀값은 등록 직후 응답 한 번만.** 페이지를 새로고침하면 다시 보이지 않고, 새로고침의 POST 재전송은 같은 이름의 연결을 또 만든다. 비밀값은 `no-store`로 내려가지만 브라우저 기록에는 남지 않는다. 등록 결과는 복사한 뒤 닫아야 한다.
- **결과는 슬래시 명령의 텍스트 그대로 `<pre>`로 보인다.** `/수집원`, `/발송내역`은 JSON이 그대로 나온다. 표로 바꾸면 보기 좋지만 서비스 코드를 건드려야 해서 이번에는 두지 않았다.
- **`/서버구성` 적용 확인은 미리보기 화면이 맡는다.** 미리보기에서 적용 버튼(`confirm=1`)을 누르는 것이 확인이다. 미리보기 없이 planId를 직접 보내도 서버 쪽 `apply`가 계획을 검증한다.
- **WEB_ENABLED를 켜면 9개 슬래시 명령이 링크 안내만 한다.** 웹 로그인이 안 되는 사람(OAuth 앱 미등록 등)은 이 기능을 잃는다. 켜기 전에 로그인이 되는지 먼저 확인해야 한다. Discord 버튼으로 이미 만든 `/서버구성` 미리보기의 [적용] 버튼은 계속 동작한다.
- **웹이 꺼지면 되돌아간다.** `WEB_ENABLED=false`로 돌리면 9개 명령이 예전처럼 동작한다(핸들러는 지우지 않았다).

## 사용자

- **`/사용량`의 USER는 웹에서 잘 안 열린다.** 슬래시 명령은 "서버 멤버면 USER"(`DISCORD_GUILD_MEMBERS_ARE_USERS`)로 통과하지만 웹은 서버 멤버십을 확인할 수 없다. `DISCORD_USER_IDS`에 오른 계정이나 관리자만 `/admin/usage`가 열리고, 나머지는 "허용되지 않았다"는 안내를 본다. 서버 멤버 전체가 쓰던 기능이 웹에서는 좁아진다.
- **`/검색`의 웹 링크는 지난 소식 목록(`/archive`)으로 간다.** 웹에 검색 페이지가 아직 없어서 결과 항목별 링크가 아니라 아카이브 한 줄이다. 검색 결과와 아카이브 내용이 같지 않으므로 "더 보기"로 오해할 수 있다.
- **구독 만들기는 DM 전용, 이름으로 해제.** `/구독`·`/구독해제`와 같다. 웹 `/me`의 학습자 구독과는 다른 기능(운영자 브리핑 구독)이다. (U8) 메뉴와 페이지 이름을 "운영자 브리핑 구독 / 운영자 브리핑 구독 해제"로 바꾸고 폼에 `/me`와 다르다는 문장을 넣었다.
- **관리 메뉴는 ADMIN 이상에게만 보인다.** USER가 `/admin/usage`를 쓰려면 주소를 알아야 한다(`/admin` 목록은 열린다).

## 남겨 둔 것

- `/일정`은 코드 주석으로 동결을 표시했고 동작은 그대로다.
- 9개 슬래시 명령의 핸들러는 지우지 않았다(제거는 웹 안정화 뒤).
