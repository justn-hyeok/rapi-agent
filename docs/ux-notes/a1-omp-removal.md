# a1-omp-removal UX 메모

- (U8에서 고침) `/취소`는 이전 슬래시 작업이 없으면 호출한 사람의 실행 중(`running`) ChatOps 작업을
  `cancel_requested`로 표시하고, chat 프로세스가 2초마다 확인해 프로세스를 멈춘다. 접수만 되고 아직
  실행 전(`prepared`/`accepted`)인 요청은 표시하지 않으므로 그때는 "라피야! 멈춰"를 안내한다.
  봇과 chat 프로세스가 다르므로 chat 서비스가 내려가 있으면 표시만 남고 멈추지 않는다.
- `/취소`에 이제 취소할 이전 작업이 거의 없으므로, 슬래시 명령 자체를 없애고 ChatOps로
  일원화하는 편이 단순하다.
- 슬래시 명령 등록을 다시 하지 않으면 Discord에 `/작업`·`/승인`이 남아 있고, 실행하면 알 수 없는
  명령 오류가 난다. 배포 직후 `npm run discord:register-commands`가 필요하다.
