# a1-omp-removal UX 메모

- `/취소`는 이제 이전 슬래시 작업 기록(`task_requests`)만 취소한다. 실행 중인 ChatOps 작업은
  봇 프로세스가 아닌 chat 프로세스가 소유하므로 `/취소`로 중단할 수 없다. 대상이 없으면
  "라피야! 멈춰"를 안내하도록 메시지를 바꿨지만, 사용자는 `/취소`가 ChatOps 작업을 멈춘다고
  기대할 수 있다. 중단 요청을 DB(`cancel_requested`)로 전달해 chat 프로세스가 폴링하게 하면
  해결되지만 이번 범위(작은 변경)를 넘는다.
- `/취소`에 이제 취소할 이전 작업이 거의 없으므로, 슬래시 명령 자체를 없애고 ChatOps로
  일원화하는 편이 단순하다.
- 슬래시 명령 등록을 다시 하지 않으면 Discord에 `/작업`·`/승인`이 남아 있고, 실행하면 알 수 없는
  명령 오류가 난다. 배포 직후 `npm run discord:register-commands`가 필요하다.
