# UX 메모 (a2-harness-adapters)

- `/ready`의 senpi 항목은 바이너리와 설정 파일만 보므로 `ok`여도 공급자 로그인이 안 된 상태일 수 있습니다. 로그인 전 `센파이로 …`는 실행 실패로만 보고되어 원인(로그인 필요)을 알기 어렵습니다. 실패 출력에 로그인 안내를 덧붙이는 편이 낫습니다.
- `센파이로`는 소유자만 인식하므로, 다른 등급이 쓰면 접두사가 그대로 요청 문장에 들어갑니다. 거절 안내가 없어 무시된 것인지 알 수 없습니다.
- 접두사 두 개(`센파이로 아스트라로 …`)를 이어 써야 하는 점이 번거롭습니다. senpi는 Codex 모델 별칭이 아닌 `provider/id`를 받는데 현재는 명시한 모델명을 그대로 넘깁니다.
- 대체 실행(Codex) 안내는 답변 첫 줄에만 있고 실행 기록(상태 조회)의 모델 칸에는 하니스가 나오지 않습니다.
