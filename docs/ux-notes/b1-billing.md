# UX 메모: 결제 (B1, 꺼짐)

- 기본은 꺼짐이다. 꺼진 동안 `/billing*`는 빈 404이고 `/me`에도 요금제 줄이 없다. 게이트웨이는 경로를 열어 두지만 봇이 404를 돌려준다.
- 켜면 학습자에게 보이는 것: 상단 "요금제" 링크, `/billing` 목록, 결제창, `/me`의 `요금제: 무료` 줄. 지금 어떤 기능도 막지 않으므로 사려는 사람이 "사면 무엇이 달라지는지" 알 수 없다. 플랜의 `features`가 비어 있어서 `supporter`는 후원 성격이다. 켜기 전에 사면 얻는 것을 정해야 한다.
- 가격 1,000원은 자리표시다. 라이브로 켤 때 플랜 파일을 안 고치면 1,000원짜리 "서포터"가 팔린다. 켜기 절차에 적었지만 코드가 막지는 않는다.
- 약관·환불 정책·사업자 정보 페이지가 없다. 결제창에도 링크가 없다. 라이브로 켜기 전에 반드시 만들어야 하고, 지금은 TODO 체크리스트뿐이다.
- 환불은 SUPERADMIN이 `/admin/billing`에서 전액 환불만 한다. 부분 환불, 사용자 본인의 환불 요청, 환불 사유 입력(고정 문구 "관리자 환불")은 없다. 청약철회 안내와 맞지 않을 수 있어 정책이 정해지면 고쳐야 한다.
- 결제창에서 `GET /billing/checkout`이 주문 행을 만든다. 로그인한 사용자가 새로고침할 때마다 `pending` 주문이 쌓인다(60분 뒤 `expired`로 정리, 삭제는 안 함). 금액은 못 바꾸지만 행 스팸은 막지 않는다.
- 결제 확인 도중 네트워크가 끊기면 "결제 확인 중이에요, 다시 결제하지 마세요"를 보여 주고 주문을 `pending`으로 둔다. 이후 이용권은 Toss 웹훅이 와야 적용된다. 웹훅 URL을 등록하지 않았다면 돈은 나갔는데 이용권이 없는 상태가 남는다. 이 경우 `/admin/billing`에서 보이지만 수동 재확인 버튼은 없다(토스 상점관리자에서 확인).
- 같은 성공 주소를 두 탭에서 동시에 열면 Toss 승인 요청이 두 번 갈 수 있다. 같은 Idempotency-Key라 한 번만 결제되고 이용권도 한 번만 늘지만, 두 번째 탭이 잠깐 오류를 볼 수 있다.
- 결제 페이지 CSP에 허용한 토스 출처는 문서 기준이며 실제 브라우저로 확인하지 못했다. 위젯이 다른 출처(카드사 인증 등)를 쓰면 결제창이 비거나 멈춘다. 테스트 모드에서 처음 켤 때 콘솔을 봐야 한다.
- 토스 일반 웹훅은 서명이 없다. 본문은 믿지 않고 `getPayment`로 다시 조회하지만, 누구나 이 URL로 조회를 유발할 수 있다(토스 API 호출 한도 소모). 한도 보호는 넣지 않았다.
- 결제 주문은 개인정보 삭제 뒤에도 남는다(법령상 거래 기록). 사용자가 `/데이터삭제`를 하면 이용권은 사라지고 환불 없이 끝난다. 삭제 미리보기 문구에는 결제 기록이 남는다는 말이 아직 없다.
- 결제 후 플랜을 플랜 파일에서 지우면 그 주문의 기간 계산·환불이 막힌다(`priceKrw: 0`으로 두라고 문서에 적음).
- `/me`의 이용권은 만료일을 한국 시간 날짜로 보여 준다. 만료 당일 자정(KST)에 끝나는 게 아니라 결제 시각 + N일이다.
