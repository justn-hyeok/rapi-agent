# U8 UX 수정: 남은 메모

레인 메모의 싼 항목 12개를 고치며 새로 생긴 점만 적는다.

## 소유자

- **결과가 메시지 본문에 남는다.** `[허용]/[거절]`, `[발송]/[건너뛰기]`, 하네스 `[반영]/[건너뛰기]/[나중에]/[되돌리기]`,
  블로그 `[게시]/[버리기]/[내리기]`를 누르면 원래 DM이 "✅ 결과 + 처리: 누구 · 언제"로 바뀌고 버튼이 사라진다.
  메시지는 2000자 안에서 원문을 잘라 쓰므로, 긴 미리보기는 끝이 "…"로 줄 수 있다.
  권한 없음·오류는 메시지를 건드리지 않고 누른 사람에게만 임시 메시지로 보인다.
- **버튼 메시지가 먼저 "생각 중"으로 응답한다.** 서버 허용처럼 느린 작업도 3초 제한에 걸리지 않지만, 편집이 실패하면
  (Discord 오류) 메시지는 그대로 남고 처리만 끝난다. 이때 다시 누르면 "이미 처리했어요" 류의 결과로 바뀐다.
- **`[돌아가기]`가 만드는 버튼은 항상 `[게시]/[수정 요청]/[버리기]`다.** PR이 닫혀 돌아온 초안 알림에는 원래 `[수정 요청]`이 없었다.
- **재알림은 한 번뿐이다.** 학습자 미리보기는 3시간 뒤(24시간이 지난 것은 제외), 블로그 PR은 승인 24시간 뒤. DM이 막혀 있으면
  그 한 번도 사라진다. 배포 직후 이미 24시간 넘게 `approved`에 머문 글은 한 번 바로 알린다.
- **마이그레이션 0027이 봇·워커보다 먼저 적용돼야 한다.** 컬럼 두 개(`learner_issues.preview_reminded_at`,
  `blog_posts.approved_reminded_at`)를 추가하고, 블로그 상태 전이(`[게시]`·`[내리기]`·PR 추적)도 새 컬럼을 쓴다.
  자동 배포(`switch-release`)는 새 마이그레이션을 먼저 적용하고(롤백 파일 `0027_owner_reminders.sql` 포함),
  수동으로 코드만 올리면 블로그 버튼과 재알림이 "column does not exist"로 실패한다. `/ready`의 migrations 항목이
  불일치를 503으로 알린다.
- **비용 알림 키가 바뀌었다.** 이미 이번 달 80%/100%를 넘겼다면 배포 직후 알림이 한 번 더 올 수 있다.

## 사용자

- **웹 해지 링크는 호 DM마다 서명된 새 링크다.** 웹이 꺼져 있으면 줄이 없다. 링크를 받은 사람이면 누구나 해지할 수 있으므로
  DM 내용을 남에게 보여 주지 말라는 안내는 따로 없다.
- **영어 요청 판정은 "동사로 시작하는 문장"만 본다.** `Please fix …`는 PR이 되고 `I think you should fix …`는 질문이다.
  `if`, `how`, `should`, `explain`, `don't`가 들어간 문장은 질문으로 둔다. 한글 판정은 그대로다.
- **버튼을 누른 뒤에 "응"이라고 쓰면 "버튼을 눌러 확정해 주세요"가 다시 나온다.** 버튼 결과는 대화 기록에 남지 않아 직전 답이 여전히 확인 문구이기 때문이다.
- **"응"에 대한 답은 직전 대화에 확인 문구가 있을 때만 나온다.** 대화가 24시간이 지났거나 채널이 다르면 평소처럼 검색으로 흐른다.

## 남겨 둔 것

- 공개 채널의 확인 버튼이 모두에게 보이는 문제(q5)는 건드리지 않았다.
- `/취소`는 `running` 상태만 멈춘다. 접수 직후(`prepared`/`accepted`)의 짧은 구간에는 "취소할 작업이 없습니다"가 나온다.
