# W1 web: UX notes

Things a user or the owner may find confusing, missing, or risky.

## 사용자

- **DM이 안 올 수 있음.** 웹에서 구독해도 DM은 라피 봇과 같은 서버에 있고 서버 멤버의 DM을 허용해야 받는다. `/me`에 한 줄로 적었지만, 웹 구독자는 Discord 서버 버튼 경로를 거치지 않아 봇과의 공통 서버를 보장할 수 없다. 실제로 막히는 사람이 나오면 발송 실패(`learner_deliveries.state='failed'`)를 `/me`에 보여 주는 편이 낫다.
- **발송이 꺼져 있으면 구독 버튼이 비활성.** `LEARNER_EXPERIMENT_ENABLED`가 꺼진 동안 `/me`는 구독 폼을 막고 이유를 보여 준다. 그 사이 Discord 버튼으로 이미 구독한 사람은 "받는 중"으로 보이지만 실제 발송은 없다.
- **해지 링크가 DM에 아직 없음.** `/u/<token>` 경로와 서명은 만들었지만(`WebPortal.unsubscribeUrl`), 발송 DM 본문은 다른 레인 영역이라 건드리지 않았다. 지금은 DM의 [그만 받기] 버튼과 `/me`로만 해지된다. DM 푸터에 링크를 넣어야 이메일 채널(M3)이 법적으로도 안전하다.
- **이메일 카드는 메일 서비스가 있을 때만.** 연결되면 `/me`에서 주소를 등록·삭제한다(`docs/ux-notes/i7-integration.md`). 서비스가 없으면 라디오는 "준비 중"으로 남는다.
- **로그인 범위.** `identify`만 요청해 사용자 이름과 ID만 읽는다. 서버 목록, 메시지는 읽지 않는다. Discord 동의 화면이 `prompt=none`이라 한 번 승인한 사람은 바로 통과한다.
- **아카이브는 로그인 없이 공개.** 발송 완료(`sent`)된 호만 나온다. 원문 링크는 추적 없이 바로 열린다(DM 링크와 달리 클릭이 집계되지 않는다). 성공 지표의 "클릭 1회 이상 활성 구독자"는 웹 아카이브에서 읽은 것을 포함하지 않는다.
- **모바일.** 서버 렌더링, 터치 영역 44px 이상, 다크모드 대응. 실제 기기 확인은 하지 않았다.

## 운영자

- **세션은 30일 슬라이딩이 아니라 고정.** 로그인 후 30일이 지나면 다시 로그인해야 한다. 로그아웃은 서버 세션도 지운다.
- **역할은 요청마다 계산.** `DISCORD_*_USER_IDS`를 바꾸면 재로그인 없이 바로 반영된다. 서버 역할(role ID)이나 Discord 관리자 권한은 웹에서 보지 못하므로(`guilds` scope 없음) 웹 ADMIN/SUPERADMIN은 사용자 ID 목록만 따른다.
- **Discord 개발자 포털에 redirect를 등록하지 않으면** 로그인이 "Invalid OAuth2 redirect_uri"로 실패한다. `WEB_ENABLED`는 켜졌는데 로그인만 안 되는 상태가 가장 흔한 첫 실수다.
- **`EMAIL_ENABLED`는 이 레인에서 추가한 한 줄 설정.** M3가 같은 키를 추가하면 병합 때 하나만 남기면 된다.
- **로그인 실패 화면이 일반적.** Discord API 오류를 사용자에게 자세히 보이지 않는다(토큰 노출 방지). 원인은 봇 로그가 아니라 지금은 남지 않는다. 필요하면 실패 사유 로깅을 추가해야 한다.
- **게이트웨이는 모든 웹 경로를 정적으로 허용**하고, 꺼져 있을 때의 404는 봇이 처리한다. 즉 `WEB_ENABLED=false`여도 게이트웨이를 통과한 요청이 봇까지 간다.
- **세션 정리는 로그인 시점에만.** 만료된 세션 행은 다음 로그인 때 지운다. 로그인이 드문 기간에는 쌓여 있지만 조회는 만료 조건을 항상 확인한다.
