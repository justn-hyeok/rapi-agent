# I7 통합: UX 메모

레인 C6·W1·W2·M2·M3·G4·Q5를 이은 작업이다. 사용자나 소유자가 헷갈리거나 위험할 수 있는 점만 적는다.

## 소유자

- **공개 질문 비용은 한 박자 늦게 잡힌다.** `PUBLIC_AGENT_BACKEND=api`의 한도 확인은 질문을 넘기기 전에 한 번,
  사용량 기록은 답이 돌아온 뒤에 한다. 동시에 여러 질문이 나가면 상한을 조금 넘길 수 있다(C6와 같은 성격).
- **공개 질문 경로는 80% 경고 DM을 보내지 않는다.** 경고·초과 DM은 `MeteredModelClient`를 거치는 호출
  (요약, 블로그 초안, 리포트)에서만 나간다. 공개 질문만 쓰는 달에는 100%에서 조용히 멈추고 사용자에게만
  "이번 달 한도에 도달했어요"가 보인다. 소유자는 `/사용량`으로 확인해야 한다.
- **비용이 0으로 남을 수 있다.** 실행기는 LiteLLM의 비용 헤더를 읽어 보내고, 헤더가 없으면 봇·chat 쪽
  `ops/model-prices.json`으로 계산한다. 둘 다 없는 모델은 0으로 기록되고 `note`에 `unknown_price`가 남는다.
  이때 상한은 작동하지 않는다.
- **한도 도달 응답은 일일 사용량을 쓰지 않는다.** 챗봇 경로에서 한도에 걸리면 `reserveAiUsage` 전에 돌려보내
  사용자의 하루 한도를 깎지 않는다. (Q5 메모의 "월 한도 도달 응답도 한 번의 사용으로 센다"는 실행기가
  `budget`을 돌려준 경우에만 해당한다.)
- **블로그 색인은 `https` 기본 URL이 있을 때만.** `RAPI_PUBLIC_BASE_URL`이 없거나 `http`이면 챗봇이 블로그
  글을 찾지 못한다. 예전에 파일에서 읽던 방식은 없앴으므로, 배포한 체크아웃에 있는 `apps/blog/content`의
  글(예: `rapi-start`)은 DB에 `published`로 들어 있을 때만 색인된다.
- **모델 클라이언트는 프로세스마다 하나씩 만든다.** 봇·chat·워커가 각자 같은 설정으로 만들고 같은
  `model_usage`에 쓴다. 80%/100% DM은 월 1회씩만 가도록 DB에서 한 번만 선점한다.

## 사용자

- **아카이브에는 가이드만 새로 보인다.** 발행된 학습자 소식 글(`kind=issue`)은 이미 보내진 호와 같은 내용이라
  목록에서 뺐다(중복 방지). 직접 주소로 열면 열린다.
- **웹의 블로그 본문은 단순 렌더링이다.** 제목, 소제목, 목록, https 링크만 살리고 나머지는 글자로 보여 준다.
  정적 블로그(`/blog/`)와 모양이 다르고 이미지·코드 블록은 나오지 않는다.
- **내린 글은 웹 아카이브에서 즉시 사라진다.** DB의 `withdrawn` 상태를 그대로 쓰므로 `RAPI_BLOG_WITHDRAWALS_FILE`
  없이도 `/archive`에서는 바로 숨겨진다. 정적 블로그와 챗봇 색인은 각자의 주기를 따른다(색인은 최대 5분).
- **`/me` 메일 주소 카드는 `EMAIL_ENABLED`와 메일 서비스가 둘 다 있을 때만 보인다.** 하나라도 없으면 예전처럼
  "이메일 (준비 중)"이 나온다. 등록은 디스코드 모달과 같은 규칙이라 같은 주소로 10분 안에 다시 누르면
  "방금 보냈어요"만 보인다.
- **POST 응답이 그대로 페이지로 나온다.** 메일 등록·삭제 결과는 리다이렉트 없이 같은 응답에 보여 주므로
  새로고침하면 브라우저가 재전송을 묻는다. 재전송해도 확인 메일 간격 제한과 CSRF가 있어 중복 발송은 없다.
- **주소를 지우면 되돌릴 수 없다.** 하드 바운스·스팸 신고된 주소만 차단 기록을 남기고 나머지는 행을 삭제한다.
  구독(DM)을 해지하면 메일도 멈추지만 주소는 남는다.
- **메일 주소 카드는 구독 여부와 무관하게 보인다.** 구독하지 않은 사람이 주소를 등록해도 메일은 구독 후에야 간다.
  카드 아래 문구로 안내했지만 구독 상태에 따라 숨기지는 않았다.
