# UX 메모: 메일 채널

- 기존 SMTP 경로(`EMAIL_TRANSPORT=smtp`, `SmtpDeliveryAdapter`)와 별개의 두 번째 메일 경로다. 학습자 메일은 `EMAIL_ENABLED`와 `EMAIL_PROVIDER`로만 켜지며 SMTP 설정은 건드리지 않는다. `EMAIL_FROM`만 공유한다.
- 주소 등록은 디스코드 모달이다. 슬래시 명령은 명령 재등록(소유자 작업)이 필요해 피했다. 대신 등록 입구가 "구독 확인 메시지의 `[메일로도 받기]`"와 "호 DM의 같은 버튼" 둘뿐이다. (U8) 메일이 켜져 있으면 주소 행이 생길 때까지 모든 호 DM에 `[메일로도 받기]`가 붙는다(`[DM이면 충분해요]`는 처음 한 번만). 주소를 등록한 뒤 지웠다면 다시 붙는다. 상시 등록 명령이 필요하면 후속으로 슬래시 명령을 추가한다.
- 확인 링크는 열기만 해서는 확인되지 않고 `[확인]` 버튼을 눌러야 한다(메일 스캐너가 1회용 링크를 소모하는 일을 막으려는 선택). 한 단계 더 거치는 대신 "링크가 이미 사용됐다"는 오류를 피한다.
- 다른 사람 주소를 입력해 확인 메일을 보내게 하는 남용을 막으려고 같은 주소로 10분에 한 번만 확인 메일이 나간다. 정상 사용자가 10분 안에 다시 등록하면 "방금 보냈어요"만 보게 된다. 메일이 오지 않을 때 학습자가 스스로 확인할 수단은 없다(스팸함 안내만 한다).
- 메일은 DM과 함께 나간다. 구독을 그만두면(`[그만 받기]`) 메일도 멈추지만, 메일 수신 거부만 하면 DM은 계속 온다. 안내 문구에 그렇게 적었다.
- 수신 거부·하드 바운스된 주소는 1년 보관 뒤 지워진다. 그 뒤 같은 주소를 다시 등록하면 새로 확인 메일을 받는다. 스팸 신고한 사람이 1년 뒤 재등록하면 다시 보낼 수 있다(본인이 직접 등록한 경우뿐).
- 주소는 ASCII 주소만 받는다. 한글 도메인·한글 로컬 파트는 거부하고 "영문 주소로 입력"이라고만 안내한다.
- 위험: 업체 웹훅이 등록되지 않으면 바운스·신고가 들어오지 않아 반송 주소로 계속 보내 도메인 평판이 나빠진다. 그래서 `EMAIL_WEBHOOK_SECRET`을 필수로 두었지만, 업체 쪽에서 웹훅 URL을 등록했는지는 코드로 확인할 수 없다. 켠 뒤 첫 발송 후 업체 대시보드의 웹훅 전달 기록을 직접 확인해야 한다.
- 위험: Postmark는 웹훅을 서명하지 않아 Basic 인증 비밀값이 유일한 방어선이다. 값이 유출되면 누구나 주소를 수신 정지시킬 수 있다(정지만 가능하고 발송·열람은 안 된다).
- 위험: 발송 결과를 추적하는 열람·클릭 픽셀은 넣지 않았다. 클릭은 기존 `/r/<토큰>` 링크로만 센다.
- 웹 매직 링크 로그인은 연결하지 않았다(W1 세션 계층이 없음). 토큰 검증 함수만 준비돼 있다.
- 운영자 발송 결과 메시지에 `메일 성공 N명 · 실패 M명`이 붙는다. 메일 발송이 도중에 죽어도 DM 결과는 영향을 받지 않는다.
- Postmark 기본 스트림(`outbound`)은 거래 메일용이다. 정기 소식은 Broadcast 스트림이 정책에 맞을 수 있어 `EMAIL_POSTMARK_STREAM`으로 바꿀 수 있게 했지만, 코드로 정책을 확인하지는 못했다. 켜기 전에 업체 정책을 확인해야 한다.
- 주소를 바꿔 다시 등록하면 이전 주소 행을 지우고 새로 만든다(트랜잭션 없이 두 문장). 두 문장 사이에 실패하면 주소가 사라지고, 학습자는 다시 등록해야 한다.
- `EMAIL_FROM`은 표시 이름 없는 주소만 받는다(`news@도메인`). 보낸 사람 이름은 업체에서 설정한다.
