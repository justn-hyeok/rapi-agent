# 자연어 ChatOps 실행과 기억

허용된 소유자가 `/대화채널`로 켠 채널에서 `라피야!`로 요청한다.
명확한 변경·배포 요청 자체가 실행 권한이다. 재승인은 요구하지 않는다.
기본 모델은 `gpt-5.3-codex-spark`다. 현재 요청의 접두·접미 지시나 `/작업`의
`모델` 선택으로 작업별 모델을 바꿀 수 있다.
기존 `/작업` → `/승인` OMP 계약과 명령은 그대로 사용할 수 있다.

| 요청 | 동작 |
| --- | --- |
| `라피야! 로그인 오류 고쳐줘` | 변경 실행을 즉시 접수 |
| `라피야! 배포해줘` | 소유자가 요청한 배포를 직접 실행 |
| `라피야! 왜 실패했는지 설명해줘. 수정하지는 말고` | 읽기 전용 답변 |
| `라피야! 지금 뭐 하는 중이야?` | 현재 채널·소유자의 최근 5개 실행 상태 |
| `라피야! 최근 작업 보여줘` | 단계, 확신의 범위, 다음 행동, 관찰 근거 |
| `라피야! 멈춰` | 현재 소유자·채널의 활성 프로세스 종료 |
| `라피야! 기억해줘: 기본 답변 언어는 한국어` | 후보 생성 후 직접 요청 근거로 승인, 저장 문구·ID·되돌리기 안내 |
| `라피야! 기억 목록 보여줘` | 최근 승인 기억 20개 |
| `라피야! 기억 <ID> 잊어줘` / `라피야! 최근 기억 잊어줘` | 지정 ID / 가장 최근 승인 기억 제외 |
| `라피야! 테스트가 될 때까지 고쳐줘` | 최대 3회, 실행 예산 8분의 목표 반복 |
| `라피야! 아스트라로 오류 고쳐줘` | 현재 요청만 `gpt-6-astra`로 실행 |
| `라피야! 문서 정리해줘, 모델: gpt-5.6-sol` | 정확한 모델 ID로 실행 |

## 구조와 권한 경계

- `apps/chat/src/run.ts`: 환경, Gateway, allowlist, 메시지 검증, Discord 전달, 단일 인스턴스 잠금.
- `router.ts`: 결정론적 한국어 라우팅과 타입 검사되는 capability catalog.
- `orchestrator.ts`: 채널 대기열, 상태·취소 우회, 기억 문맥, 실행·반복·보고.
- `executor.ts`: Codex 프로세스 그룹, timeout/취소, 제한된 출력, Git 관찰, 임시 파일 정리.
- `packages/contracts/src/chatops.ts`: 외부 메시지·실행·증거·기억 Zod 계약과 비밀 마스킹.
- `packages/db/src/chatops-store.ts`: PostgreSQL 원자적 메시지 접수, 실행·기억 저장.
- `0004_chatops_capabilities.sql`: 별도 실행·이벤트·기억·기억 이벤트 테이블과 강제 전이 trigger.

질문은 Codex read-only sandbox, 명시 실행은 소유자가 선택한 broad authority로
실행한다. 인용문, 코드 블록, 설명, 부정, 조건부·모호한 표현은 변경 권한을 얻지
않는다. 라우터는 작은 명시 구문 집합이며 이해하지 못하는 표현은 답변으로 남는다.
기억과 이전 대화는 JSON 참고 데이터로만 전달하고 현재 요청만 권한 근거로 삼는다.
기억 텍스트로 라우터나 sandbox를 변경하지 않는다.

모델 지시를 생략하면 Spark를 사용한다. `스파크`, `아스트라`, `솔`, `테라`,
`루나`는 서버가 아는 정확한 ID로 변환한다. `모델: gpt-…` 형식은 안전한 모델 ID
문자만 허용하고 Codex CLI에 독립 인자로 전달한다. 선택한 모델은 실행 행과 상태
응답에 남는다. 계정이 지원하지 않는 모델은 다른 모델로 몰래 대체하지 않고 해당
작업을 실패로 기록한다.

## 실행 기록과 완료 의미

메시지 중복 검사와 `prepared` 실행 생성은 한 트랜잭션이다. 같은 Discord ID를
재전달해도 다시 실행하지 않는다. `prepared`는 대기열에 있는 요청도 포함한다.

```text
prepared → accepted → running → reported_done → verified
   │           │         ├──→ failed
   └───────────┴─────────┴──→ cancel_requested → cancelled / failed
   └───────────┴─────────┴─────────┴──────────→ interrupted (재시작)
```

`running → running` 이벤트는 시도 시작·실패 관찰을 보존한다. 목표 자체는 실행
중이고 개별 시도의 exitCode가 실패를 표현한다. terminal 전이는 DB가 거부한다.
`reported_done → verified`만 기존 관찰에 묶인 제한적인 후속 전이다.
이벤트의 UPDATE/DELETE는 거부한다. 각 이벤트는 실행·task digest에 묶이며 UTC
생성 시각을 갖는다. 실행 행에는 생성/갱신 시각, 모델, scope, 원본 메시지 ID,
마스킹된 task text의 SHA-256, 마지막 증거를 둔다. 원문 task나 child 환경은
실행 메타데이터에 저장하지 않는다. 기존 대화 테이블에는 마스킹된 대화가 남는다.

Codex 종료 0은 **실행기 보고**이며 목표 달성 확인이 아니다. 호스트가 직접 실행한
`git diff --check`는 그 검사에 대해서만 근거를 남긴다. Git HEAD, porcelain status,
tracked diff와 untracked 내용 digest를 함께 사용해 변경본을 식별한다. 검사 전후
변경본이 같을 때만 task digest와 revision에 연결된 검사 결과를 저장한다.
현재 자동 경로는 `reported_done`에서 멈춘다. `verified`는 이미 저장된 동일
revision의 통과 근거를 재사용해야 하며, 전체 목표·배포·CI 성공으로 해석하지 않는다.
임의 프로젝트의 테스트 명령이나 목표 완료 판정기를 자동 추측하지 않는다.

## 취소, 재시작과 한계

상태·취소는 채널 대기열을 우회한다. 정상 DB 경로에서 먼저 `cancel_requested`를
기록하고 활성 프로세스 그룹에 SIGTERM, 필요하면 1초 후 SIGKILL을 보낸다.
프로세스 close를 기다려 `cancelled`를 기록한다. DB 장애도 로컬 종료 신호를 막지
않으며 상태 기록 실패는 미확정으로 알린다. 취소는 같은 소유자의 현재 채널 작업을
대상으로 하고, 다른 채널·소유자 또는 이후 대기 작업을 취소하지 않는다.
이미 발생한 외부 효과를 되돌리는 기능은 아니다.

시작 시 PostgreSQL advisory lock으로 단일 Gateway를 보장한 뒤 남은 활성 상태를
`interrupted`로 바꾼다. 자동 재실행하지 않는다. 기존 systemd unit과 기본
control-group 종료 동작을 유지한다. systemd 밖에서 부모만 강제 종료하거나 자식이
별도 세션/외부 작업을 만들면 그 외부 작업까지 종료를 보장할 수 없다. 재시작 후에는
이전 PID를 추측해 죽이지 않는다. 별도 실행기의 `/작업` OMP 실행은 자연어 상태·취소
목록에 포함하지 않으며 기존 slash 흐름으로 관리한다.

## 기억과 자원 한도

기억 scope는 guild/channel/owner다. 후보→승인→superseded 또는 forgotten 전이를
revision과 digest로 검사한다. 내용·출처는 불변이며 변경 내용은 새 기억으로 만든다.
현재 UX는 명시 저장의 자동 승인과 forget을 제공하고 supersede는 저장소 API로
제공한다. 잊기는 향후 승인 기억 pack에서 제외하는 것으로, 대화 이력·감사 이력·
백업의 물리적 삭제는 아니다.

기억 한 항목 2,000자, pack 6,000자, 최근 대화 6개, 응답 16,000자, child 로그
16,000자, 결과 파일 읽기 64KB, Git 명령 출력 1MB 및 5초, untracked 100개/1MB로
제한한다. 범위를 넘는 Git 관찰은 생략하며 진전을 추측하지 않는다. 채널 대기열은
20개, 동시 대기 채널은 100개다. 각 Codex 시도는 최대 3분이다. 루프는 정상적인
비영 종료와 Git 변화가 둘 다 있을 때만 재시도한다. 동일 revision 반복, 진전 없음,
인증·rate-limit, timeout, 취소, 3회/8분 예산에 멈춘다. 관찰·DB·전달 시간과 종료
유예는 실행 예산 외의 작은 오버헤드가 될 수 있다.

장기 작업은 접수, 30초를 넘긴 시도의 1회 진행 안내, 재시도, 최종 상태를 보낸다.
주기적인 상태 메시지는 보내지 않는다. Discord HTTP에는 10초 timeout을 적용하고
mentions는 비활성화한다. 전달 실패가 실행 완료 상태를 바꾸지 않는다. 자동 발송
재시도/outbox는 없으므로 전달 장애 후 상태 조회로 확인한다. 중복 요청 재실행은
막지만 실패한 답변을 자동 재전송하지는 않는다.

임시 출력 디렉터리는 시도 종료 시 삭제하며 재시작 시 자신의 `run-XXXXXX` 잔여
디렉터리만 정리한다. 비밀 이름의 환경 변수는 child에서 제외하고 입력·출력·기억·
Git status에는 알려진 credential 형태와 주입된 비밀값을 마스킹한다. 임의 자연어에
숨겨진 모든 비밀을 식별하는 보장은 없으며 모델의 자유 형식 출력은 독립 검증이 아니다.
