# 남은 데이터 정리 3개

범위: 기록 보존기간 만료, 90일 지난 발송 수신정보 축소, 확정된 삭제 요청 처리.
VM 전원·재부팅 작업은 하지 않는다. 기존 서비스의 코드 배포·재시작은 기존 승인
범위에서 진행한다.

- 수집 원본 메타데이터는 공개 1년·비공개 90일 뒤 참조 관계를 정리하고 제거한다.
  발송·작업 감사는 1년 뒤 종료된 건만 정리한다. 진행 중인 발송·실행은 보호한다.
- 발송 감사의 수신자와 idempotency key는 90일 뒤 별도 비밀키의 HMAC으로 축소한다.
  현재 구독 설정은 계속 발송하는 데 필요한 정보이므로 자동 익명화하지 않는다.
- `/데이터삭제 요청`은 본인 정보 또는 소유자 권한의 수집 항목·수집원만 대상으로
  한다. 미리보기와 별도 `/데이터삭제 확정`을 거치며 다른 사용자는 확정·조회할 수
  없다. 기존 작업이 실행 중이면 대기하고, DB·파생 결과·등록된 게시 파일을 제거한다.
  공개 글은 영속 철회 목록으로 차단한다.
- 서버가 관리하는 백업은 DB 밖의 catalog에 등록하고 30일 만료한다. 삭제 요청은
  기존 백업 파일이 실제로 사라지는지 확인한 뒤 완료한다. 기한만 보고 완료 처리하지
  않는다. 요청·철회 기록은 백업과 독립적으로 보관해 추적한다.

검증: 전용 PostgreSQL DB에서 보관기간 경계, 활성 작업 보호, append-only 기록
보호, HMAC·반복 실행, 잘못된 사용자·확정 만료, 실제 파일 제거·경로/해시 보호,
백업이 남아 있는 동안의 대기와 실제 만료 후 완료를 확인한다. 실제 VM 재부팅은
검증 대상에서 제외한다.
