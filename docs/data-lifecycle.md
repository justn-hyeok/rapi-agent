# 데이터 보관·삭제 운영

`v0.1.2`는 원본 본문 만료에 이어 메타데이터 만료, 발송 감사의 수신정보 축소,
확정된 삭제 요청과 백업 만료 추적을 실행한다. VM 재부팅은 하지 않는다.

## 자동 보존기간

- 공개 원본 메타데이터는 1년, 비공개 원본 메타데이터는 90일 뒤 제거한다.
- 발송·승인·외부 실행 감사는 1년 뒤 종료된 기록만 제거한다. 최근에 완료되거나
  수정된 작업과 아직 실행 중인 작업·발송은 유지한다.
- 종료된 발송의 주소·수신자 ID와 중복 발송 키는 90일 뒤 전용 비밀키의 HMAC으로
  축소한다. 해당 과거 발송은 다시 전송하지 않는다. 현재 구독의 수신 설정은
  앞으로 발송하는 데 필요하므로 이 자동화에서 바꾸지 않는다.
- 대화 원문은 30일 뒤 제거하고, 사용자가 명시적으로 승인한 장기 기억은 유지한다.
  기억의 변경 이력은 1년 뒤 제거한다. 본인 정보 삭제를 확정하면 장기 기억도 지운다.
- 최소한의 키가 있는 이벤트 차단 표시는 삭제된 과거 이벤트의 재수집을 막는다.
  원본·주소·체크섬을 그대로 보관하는 기록이 아니다.

`rapi-privacy-maintenance.timer`는 매일 04:10 UTC에 실행한다. 최근 26시간 안에
성공한 실제 백업이 없으면 중단한다. `rapi-privacy-worker.service`는 확정된 삭제
요청과 백업 추적을 처리하며 실패 상태는 monitor의 `data_lifecycle`에 반영한다.

## 삭제 요청

```text
/데이터삭제 요청 종류:내 정보
/데이터삭제 확정 요청id:<미리보기의 요청 UUID>
/데이터삭제 상태 요청id:<같은 UUID>
```

본인 정보는 본인의 대화·답변·기억·구독·작업·사용 기록이다. 공유 수집원의 공개
자료는 본인 정보 요청으로 삭제하지 않는다. 수집 항목·수집원 삭제는 소유자
권한에서 해당 UUID를 지정한다. 연결된 브리핑·발송 감사·게시 파일도 함께 처리한다.
공개 URL·목록·RSS는 영속 철회 목록으로 닫는다.

미리보기만으로는 삭제하지 않는다. 요청을 만든 같은 사용자가 같은 서버에서
24시간 안에 확정해야 한다. 항목·수집원 확정 시에도 소유자 권한을 다시 확인한다.
확정 시 대상 영역을 다시 계산하고 수집원·구독을 중지해 새 수집·발송을 막는다.
진행 중인 발송·실행·답변은 종료 후 처리한다. 과거 다중 사용자 대화의 답변 소유
관계가 불분명하면 요청을 대기 상태로 남겨 다른 사람의 내용을 지우지 않는다.

등록된 `.mdx` 파일은 허용된 게시 경로와 등록 checksum이 일치할 때만 제거한다.
변경된 파일·심볼릭 링크·허용 경로 밖의 파일은 보존하고 요청을 완료로 표시하지
않는다. 다른 사람의 작업 저장소·실행기로 수정한 프로젝트·전달받은 외부 메일함은
삭제 대상이 아니다. 공개 자료를 포함한 Git 릴리스 이력도 강제로 다시 쓰지 않는다.

## 백업 추적

현재 서비스의 `rapi-*.dump`와 운영 복구 증거의 `.dump` 사본을 함께 추적한다.
운영 사본은 `RAPI_BACKUP_CATALOG_ROOTS` 아래에서 `register-backups.mjs`로 등록한다.
등록 파일의 시각·크기가 달라지면 자동 삭제하지 않고 확인을 요구한다.
백업 catalog와 삭제 ledger는 `/var/lib/rapi/`의 mode 0600 파일로 DB 밖에 보관한다.
백업과 DB 삭제는 같은 PostgreSQL advisory lock을 사용하므로 삭제가 진행 중인
백업을 추적 목록에서 놓치지 않는다. 나중에 등록된 복구 사본도 추적 목록에 넣는다.
ledger 쓰기는 잠금으로 직렬화한다. 프로세스 강제 종료로 `.lock`이 남으면 worker와
maintenance를 정지하고 잠금의 PID가 종료됐는지 확인한 후 해당 잠금만 제거한다.
이를 확인하지 않고 다른 프로세스의 잠금을 자동 제거하지 않는다.

삭제 후 상태는 `waiting_backups`다. 예상 시각이 지났더라도 등록된 이전 백업
파일이 남아 있으면 완료하지 않는다. 실제 파일이 사라진 뒤 `completed`가 된다.
DB 복원 때문에 요청 기록이 사라지면 외부 ledger에서 발견해
`restore_reconciliation_required`로 표시한다. 복원 운영자는 앱을 공개하기 전에
그 요청을 재조정해야 한다. 현재 기능이 백업 복원 자체를 자동 수행하지는 않는다.

## 설치·배포

전용 `PRIVACY_HMAC_KEY`는 32 random bytes의 hexadecimal 값으로 private `.env`에
생성한다. 값은 채팅·Git·로그에 남기지 않는다. 주어진 명령·백업 사본 등록·worker
설치와 새 slash 명령 등록 후 최초 maintenance를 실행하고 monitor 상태를 확인한다.

Migration `0013_data_lifecycle.sql`는 append-only 감사의 최근 기록 보호를 유지하면서
보존기간 만료 또는 확정된 본인 삭제의 parent cascade만 허용한다. 일반적인 이벤트
변경·직접 삭제는 계속 거부한다. 스키마가 달라지는 배포는 `switch-data-lifecycle.mjs`
가 서비스를 정지하고 migration·코드 전환을 함께 실행한다. 활성화 전 실패하면
새 기능이 아직 데이터를 처리하지 않은 경우에만 스키마와 코드를 되돌린다.
